# Тести для кошторисного модуля

## Роль

Senior TypeScript-розробник, що пише production-код з тестами на vitest.

## Мета

Розширити `app/src/quote.test.ts` тестами на межові випадки для
`app/src/quote.ts` і виявити будь-які реальні дефекти, які ці випадки
розкривають.

## Контекст

- Ціль: `app/src/quote.ts` — три функції: `estimateTotalCents`,
  `splitInstallments`, `formatMoney`.
- Існуючі тести: `app/src/quote.test.ts` (лише happy path, 4 тести).
- Домен: суми — цілі числа в центах, щоб уникнути похибок float.
- Запуск: `cd app && npm test`.

## Обмеження

- НЕ міняти публічний API (сигнатури `QuoteInput`, назви й типи експортів).
- НЕ додавати залежностей.
- Продакшн-код (`quote.ts`) можна правити ЛИШЕ якщо тест довів реальний
  дефект — і тоді запис про це обов'язковий у нотатках прогону.
- Стиль і структура тестів — як у наявному файлі (`describe`/`it`, українські
  назви кейсів).

## Acceptance criteria

- [ ] Додано тести на: `hours = 0`, `discountPercent = 0` і `= 100`,
      `discountPercent` не задано (default).
- [ ] Додано тест на округлення `estimateTotalCents` (дробовий проміжний
      результат, напр. непарна сума × непарний відсоток знижки).
- [ ] Додано тест, що суми з `splitInstallments` **у сумі дорівнюють
      вихідній сумі** (не лише що масив має правильну довжину) для випадку,
      що не ділиться націло (напр. `100` на `3` частини).
- [ ] Додано тест на `formatMoney` для `0` та від'ємного значення.
- [ ] Якщо якийсь із нових тестів падає на поточному `quote.ts` — це
      зафіксований дефект: він виправляється мінімальною зміною, і сам факт
      «до/після» описано в підсумку.
- [ ] `cd app && npm test` завершується зелено.

## Формат відповіді

1. Список нових тестів і що кожен перевіряє.
2. Якщо знайдено дефект — файл:рядок, вхід, що ламався, і диф виправлення.
3. Підсумок: скільки тестів було/стало, чи все зелено.

## Stop

Після зелених тестів і підсумку — зупинись. Не рефактори код поза межею
знайденого дефекту і не додавай нових фіч.

```xml
<context>
  <target>app/src/quote.ts</target>
  <tests_file>app/src/quote.test.ts</tests_file>
  <domain>Суми — цілі числа в центах</domain>
  <run>cd app &amp;&amp; npm test</run>
</context>
<constraints>
  <no>міняти публічний API</no>
  <no>додавати залежності</no>
  <production_code_change>лише якщо тест довів реальний дефект, з описом у нотатках</production_code_change>
</constraints>
<acceptance>
  <item>hours=0, discountPercent=0 та =100, discountPercent не задано</item>
  <item>округлення estimateTotalCents на дробовому проміжному результаті</item>
  <item>sum(splitInstallments(...)) === totalCents для суми, що не ділиться націло</item>
  <item>formatMoney(0) і formatMoney(від'ємне)</item>
  <item>npm test зелений</item>
</acceptance>
<format>Список нових тестів → дефект (файл:рядок, вхід, диф) якщо є → підсумок</format>
<stop>Після зелених тестів і підсумку. Без рефакторингу поза межею дефекту.</stop>
```

> **Нотатка про діалект:** різниці у якості відповіді між markdown- і

> програмно (легше валідувати структуру), markdown — коли пише людина.
