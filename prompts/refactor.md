# Рефакторинг під захистом тестів

## Роль

Senior TypeScript-розробник, що покращує структуру коду, не змінюючи його
зовнішню поведінку.

## Мета

Зробити вказану ділянку коду простішою для читання/супроводу, зберігши
ідентичний вхід/вихід для всіх існуючих і нових межових випадків.

## Контекст

- Ціль: конкретна функція, вказана окремо (напр. `splitInstallments` у
  `app/src/quote.ts`).
- Тести-гарант: `app/src/quote.test.ts` — мають лишитись зеленими без жодної
  зміни очікуваних значень у самих тестах.
- Запуск: `cd app && npm test && npm run typecheck`.

## Обмеження

- НЕ міняти публічний API (сигнатуру, типи, назву експорту).
- НЕ міняти жодного `expect(...).toBe(...)` у тестах — якщо тест довелось
  змінити, це вже не рефакторинг, а зміна поведінки.
- Одна ділянка коду за раз — не "заодно" покращувати сусідні функції.

## Acceptance criteria

- [ ] Тести до рефакторингу зелені, тести після рефакторингу зелені —
      без жодної зміни в файлі тестів.
- [ ] `npm run typecheck` без помилок.
- [ ] Диф не зачіпає файли поза вказаною ціллю.
- [ ] Коротко пояснено, чому нова версія читабельніша/коротша (не просто
      "стало краще").

## Формат відповіді

Диф зміни + 1-2 речення обґрунтування.

## Stop

Після зеленого прогону і диф — зупинись. Не рефактори більше, ніж попросили,
навіть якщо бачиш інші можливості.

## Той самий промпт у XML-діалекті

```xml
<task>Рефакторинг вказаної функції без зміни поведінки</task>
<role>Senior TypeScript-розробник, покращує структуру коду</role>
<context>
  <target_function>вказується окремо, напр. splitInstallments у app/src/quote.ts</target_function>
  <safety_net>app/src/quote.test.ts — мають лишитись зеленими без змін</safety_net>
  <run>cd app &amp;&amp; npm test &amp;&amp; npm run typecheck</run>
</context>
<constraints>
  <no>міняти публічний API</no>
  <no>міняти expect(...) у тестах</no>
  <rule>одна ділянка коду за раз</rule>
</constraints>
<acceptance>
  <item>тести зелені до і після, файл тестів не змінено</item>
  <item>typecheck без помилок</item>
  <item>диф не зачіпає файли поза ціллю</item>
  <item>коротке обґрунтування, чому це читабельніше</item>
</acceptance>
<format>Диф + 1-2 речення обґрунтування</format>
<stop>Після зеленого прогону і дифу. Без додаткового рефакторингу.</stop>
```

> **Нотатка про діалект:** без різниці у виборі рефакторингу — обидва
> діалекти дали той самий результат (заміна ручного циклу заповнення на
> `Array.from` у `splitInstallments`). XML не додав переваги на такій
> короткій, лінійній задачі.
