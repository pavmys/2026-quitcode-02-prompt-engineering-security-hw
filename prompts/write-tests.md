# Написати регресійні тести

## Роль

Senior TypeScript-розробник, що пише production-код з тестами на vitest.

## Мета

Додати регресійні тести для вказаної функції, які фіксують її поточну
задокументовану поведінку на нетривіальних вхідних даних — без зміни коду
самої функції.

## Контекст

- Ціль: одна функція за вказівкою (напр. `estimateTotalCents` у
  `app/src/quote.ts`).
- Тести: `app/src/quote.test.ts`, стиль — `describe`/`it`, українські назви.
- Домен: суми — цілі числа в центах; вхід може містити дробові `hours`.
- Запуск: `cd app && npm test`.

## Обмеження

- НЕ змінювати код цільової функції — лише тестовий файл.
- НЕ дублювати вже наявні тести (спершу прочитати `quote.test.ts`).
- Один тест — один сценарій; без умовної логіки всередині `it`.

## Acceptance criteria

- [ ] Додано ≥1 тест на нетривіальний вхід, якого раніше не було (дробові
      значення, межа типу, комбінація параметрів).
- [ ] Тест явно порівнює з обчисленим вручну очікуваним значенням (не з
      результатом самої функції).
- [ ] `cd app && npm test` залишається зеленим після додавання.
- [ ] Якщо новий тест ловить реальний дефект — про це сказано прямо, а не
      тест підлаштовано під баг.

## Формат відповіді

Диф нового тесту (або тестів) + одне речення, що саме він фіксує.

## Stop

Після зеленого прогону — зупинись. Виправлення коду — це вже `debug`-промпт,
не цей.

---

## Той самий промпт у XML-діалекті

```xml
<task>Написати регресійні тести для існуючої функції без зміни її коду</task>
<role>Senior TypeScript-розробник, пише тести на vitest</role>
<context>
  <target_function>вказується окремо, напр. estimateTotalCents у app/src/quote.ts</target_function>
  <tests_file>app/src/quote.test.ts</tests_file>
  <run>cd app &amp;&amp; npm test</run>
</context>
<constraints>
  <no>змінювати код цільової функції</no>
  <no>дублювати наявні тести</no>
  <rule>один тест — один сценарій</rule>
</constraints>
<acceptance>
  <item>новий тест на нетривіальний, раніше не покритий вхід</item>
  <item>очікуване значення пораховане вручну, а не взяте з виклику функції</item>
  <item>npm test зелений після додавання</item>
  <item>якщо тест ловить дефект — це прямо сказано</item>
</acceptance>
<format>Диф тесту + одне речення, що він фіксує</format>
<stop>Після зеленого прогону. Виправлення коду — окремий (debug) промпт.</stop>
```

> **Нотатка про діалект:** без помітної різниці в результаті. Єдине —
> XML-версія трохи чіткіше розводить "не займай target_function" від "тести в
> tests_file" завдяки окремим тегам, тоді як у markdown це один пункт
> обмежень; на такому короткому промпті це не вплинуло на виконання.
