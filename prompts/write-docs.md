# Документація модуля

## Роль

Технічний письменник-розробник: пишеш документацію, яку сам би хотів прочитати
перед тим, як викликати чужий код.

## Мета

Створити або оновити `README.md` цільового модуля: публічний API, контракт
кожної функції (вхід/вихід/межові випадки), команди запуску тестів.

## Контекст

- Ціль: `app/src/quote.ts` (експортований API) + `app/src/quote.test.ts`
  (щоб зрозуміти, які межові випадки вже покриті).
- Аудиторія: розробник, який ще не бачив цей файл, але вміє TypeScript.
- Немає наявного `app/README.md` — писати з нуля, якщо він порожній/відсутній.

## Обмеження

- НЕ змінювати код у `src/` — лише документація.
- НЕ копіювати JSDoc дослівно — переказати контракт своїми словами, з
  прикладом виклику.
- Якщо в коді є недокументована поведінка або відома вада — явно позначити
  її попередженням (⚠️), а не замовчувати.

## Acceptance criteria

- [ ] Для кожної експортованої функції: сигнатура, опис полів входу (таблиця
      або список), опис округлення/меж, приклад виклику.
- [ ] Явно згадано поведінку на межових значеннях, яку покривають тести
      (0, знижка 100%, `parts <= 0` тощо).
- [ ] Секція команд: `npm test`, `npm run typecheck`.
- [ ] Без вигаданих можливостей, яких немає в коді.

## Формат відповіді

Готовий Markdown-файл `README.md` цілком (не диф із контекстом навколо).

## Stop

Після README — зупинись. Не пропонуй рефакторинг коду, навіть якщо
документування виявило незручний API.

```xml
<task>Створити/оновити README цільового модуля</task>
<role>Технічний письменник-розробник</role>
<context>
  <source>app/src/quote.ts (публічний API)</source>
  <existing_tests>app/src/quote.test.ts</existing_tests>
  <audience>Розробник, що ще не бачив цей файл</audience>
</context>
<constraints>
  <no>змінювати код у src/</no>
  <no>копіювати JSDoc дослівно</no>
  <rule>відому ваду чи недокументовану поведінку позначати попередженням, не замовчувати</rule>
</constraints>
<acceptance>
  <item>сигнатура + опис полів + округлення/межі + приклад для кожної функції</item>
  <item>межові випадки з тестів згадано явно</item>
  <item>секція команд: npm test, npm run typecheck</item>
  <item>без вигаданих можливостей</item>
</acceptance>
<format>Повний README.md, не диф</format>
<stop>Після README. Без пропозицій рефакторингу коду.</stop>
```

> **Нотатка про діалект:** без відчутної різниці. Обидва варіанти дали
> однаковий за змістом README ([`app/README.md`](../app/README.md)); XML
> трохи допоміг не забути жодного обмеження при генерації одразу цілого
> файлу (кожен `<constraint>` — окремий пункт-чеклист), але це радше зручність
> читання самого промпту, ніж різниця у виводі моделі.
