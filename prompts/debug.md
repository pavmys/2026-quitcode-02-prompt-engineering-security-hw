# Дебаг за баг-репортом

## Роль

Senior TypeScript-розробник, що відповідає за продакшн. Спершу відтворюєш
баг, потім лагодиш — ніколи навпаки.

## Мета

Відтворити описану поведінку, знайти рядок коду, що є її причиною, і
виправити мінімальною зміною, не чіпаючи нічого поза причиною.

## Контекст

- Ціль: `app/src/quote.ts` + `app/src/quote.test.ts`.
- Баг-репорт (приклад для цього прогону): "виклик `splitInstallments(100, -1)`
  або з `parts = 0` замість зрозумілої помилки або кидає некерований
  `RangeError: Invalid array length`, або мовчки повертає `[]`".
- Запуск: `cd app && npm test`.

## Обмеження

- НЕ виправляй нічого, доки баг не відтворено тестом, що падає.
- НЕ розширюй фікс на несуміжну поведінку ("заодно" полагодити інше).
- Виправлення — найменша зміна, що усуває причину, а не symptom-patch
  (напр. не `try/catch` навколо виклику, а валідація на вході).

## Acceptance criteria

- [ ] Написано тест, що відтворює баг-репорт і **падає** на поточному коді
      (доказ, що причина знайдена правильно).
- [ ] Вказано файл:рядок кореневої причини.
- [ ] Виправлення — мінімальний диф; після нього новий тест і всі старі —
      зелені.
- [ ] Описано "до" (як саме ламалось) і "після" (яка тепер поведінка).

## Формат відповіді

1. Крок відтворення (команда/виклик, що падає).
2. Коренева причина: файл:рядок + чому.
3. Диф фіксу.
4. До/після одним реченням кожне.

## Stop

Після зеленого прогону з фіксом — зупинись. Не переходь до інших функцій,
навіть якщо в них видно схожий патерн (це окремий debug-запуск).

## Прогін (2026-09-14)

1. **Відтворення:** `splitInstallments(100, -1)` → `RangeError: Invalid array
   length` (некерований крах); `splitInstallments(100, 0)` → мовчки `[]`.
2. **Коренева причина:** [`app/src/quote.ts:31`](../app/src/quote.ts) (до
   фіксу) — `new Array(parts)` не валідував `parts` перед створенням масиву
   від'ємної/нульової довжини.
3. **Фікс:** додано перевірку на початку функції —
   `if (!Number.isInteger(parts) || parts < 1) throw new Error(...)`.
4. **До:** крах процесу або тиха втрата даних (`[]` замість помилки). **Після:**
   явний, керований `Error` з описом, що саме не так.

Регресійні тести — у `app/src/quote.test.ts` ("кидає помилку для parts <= 0…",
"кидає помилку для нецілого parts"). `cd app && npm test` — 15/15 зелено.

> **Нотатка про діалект:** різниці не помітив — обидва діалекти однаково
> наполягли на "спершу тест, що падає", що і є найважливішою частиною цього
> промпту (без цього кроку легко "полагодити" не той рядок).
