# quote — кошторисний модуль

Крихітний TypeScript-модуль для розрахунку кошторису проєкту. Усі суми — цілі
числа в **центах**, щоб уникнути похибок float.

## API

### `estimateTotalCents(input: QuoteInput): number`

Рахує вартість проєкту з урахуванням знижки.

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `hours` | `number` | так | Оцінка робіт у годинах (дробові значення допустимі) |
| `rateCents` | `number` | так | Ставка за годину, у центах (напр. `5000` = $50.00) |
| `discountPercent` | `number` | ні, за замовчуванням `0` | Знижка у відсотках, `0..100` |

Результат округлюється до найближчого цента (`Math.round`).

`discountPercent` має бути в межах `0..100`; інакше функція кидає `Error`
(до фіксу — знахідка `prompts/security-review.md` — вихід за межі приймався
мовчки й давав від'ємну або "надувну" суму).

> ⚠️ Функція досі **не валідує** знак `hours`/`rateCents` — від'ємні значення
> приймаються без помилки. Викликач відповідає за це до окремого фіксу.

### `splitInstallments(totalCents: number, parts: number): number[]`

Ділить суму на `parts` платежів. Якщо сума не ділиться націло, залишок (у
центах) розподіляється по **першим** платежам — по одному центу на платіж,
поки залишок не вичерпається. Сума елементів масиву завжди дорівнює
`totalCents`.

```ts
splitInstallments(100, 3); // [34, 33, 33] — сума = 100
```

`parts` має бути цілим числом `>= 1`; інакше функція кидає `Error` з описом
проблеми (до фіксу цього дефекту `parts <= 0` міг або крашнути процес, або
мовчки повернути `[]` — див. `docs/injection-report.md`-подібний "before/after"
у Task A нотатках).

### `formatMoney(cents: number): string`

Форматує центи у рядок на кшталт `"$1,234.50"`. Підтримує `0` та від'ємні
значення (`"-$5.00"`).

## Тести

```bash
npm test        # vitest run
npm run typecheck
```

Тестове покриття веде облік межових випадків: нуль, знижки `0`/`100`/не
задано, округлення дробових проміжних результатів, дробові `hours`, сума
частин при неточному діленні, `parts <= 0` та нецілий `parts`.
