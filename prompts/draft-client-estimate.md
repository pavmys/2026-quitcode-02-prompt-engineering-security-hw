# Клієнтський лист-кошторис

## Роль

Акаунт-менеджер агенції, що готує лист клієнту на основі розрахунку з
кошторисного модуля.

## Мета

Написати короткий, ввічливий лист клієнту з підсумком кошторису: загальна
сума, знижка (якщо є), графік платежів — використовуючи **лише** цифри, що
реально пораховані `estimateTotalCents`/`splitInstallments`/`formatMoney`.

## Контекст

- Джерело чисел: `app/src/quote.ts` (`estimateTotalCents`,
  `splitInstallments`, `formatMoney`).
- Вхідні дані для листа задаються окремо (hours, rateCents,
  discountPercent, кількість платежів) — не вигадуються.
- Аудиторія: клієнт агенції, не розробник — без технічного жаргону
  ("cents", "rounding") у тексті листа.

## Обмеження

- НЕ вигадувати жодної суми, дати чи умови, якої немає у вхідних даних.
- НЕ обіцяти нічого поза кошторисом (терміни, гарантії) — тільки цифри.
- Довжина листа: 100-150 слів.
- Формат сум у листі — через `formatMoney`, не сирі центи.

## Acceptance criteria

- [ ] Сума в листі точно дорівнює `estimateTotalCents(...)`, відформатована
      `formatMoney`.
- [ ] Кількість і суми платежів точно дорівнюють `splitInstallments(...)`;
      якщо суми відрізняються між платежами (залишок), це видно з тексту,
      а не приховано.
- [ ] Знижка згадана, лише якщо `discountPercent > 0`.
- [ ] Немає жодної цифри, якої немає у вхідних даних або в результаті
      обчислень.

## Формат відповіді

Готовий текст листа (українською або англійською — за вказівкою), без
пояснень до нього.

## Stop

Після листа — зупинись. Не пропонуй інші тексти (email subject, follow-up)
без окремого запиту.

## Той самий промпт у XML-діалекті

```xml
<task>Скласти клієнтський лист-кошторис на основі чисел з quote-модуля</task>
<role>Акаунт-менеджер агенції</role>
<context>
  <numbers_source>app/src/quote.ts (estimateTotalCents, splitInstallments, formatMoney)</numbers_source>
  <inputs>hours, rateCents, discountPercent, кількість платежів — задаються окремо</inputs>
  <audience>Клієнт, не розробник — без технічного жаргону</audience>
</context>
<constraints>
  <no>вигадувати суми, дати чи умови поза вхідними даними</no>
  <no>обіцяти щось поза кошторисом</no>
  <length>100-150 слів</length>
  <money_format>через formatMoney, не сирі центи</money_format>
</constraints>
<acceptance>
  <item>сума листа == estimateTotalCents(...), через formatMoney</item>
  <item>платежі листа == splitInstallments(...), включно з нерівним залишком</item>
  <item>знижка згадана лише якщо discountPercent &gt; 0</item>
  <item>жодної цифри поза вхідними даними/обчисленнями</item>
</acceptance>
<format>Готовий текст листа, без пояснень</format>
<stop>Після листа. Без додаткових текстів без окремого запиту.</stop>
```

## Прогін (2026-09-14) — приклад

Вхід: `hours=40, rateCents=7500, discountPercent=15`, 3 платежі.
Обчислення: `estimateTotalCents` → `255000` центів → `formatMoney` →
`"$2,550.00"`; `splitInstallments(255000, 3)` → `[85000, 85000, 85000]` →
`"$850.00"` кожен (сума ділиться націло, без залишку).

> Доброго дня!
>
> Ділимось кошторисом на обговорений обсяг робіт (40 год за ставкою
> $75.00/год), з урахуванням знижки 15%: **$2,550.00**.
>
> Пропонуємо розбити оплату на 3 рівні платежі по **$850.00** кожен —
> перед стартом, у середині та по завершенню робіт.
>
> Якщо графік чи обсяг потребують коригувань — дайте знати, підготуємо
> оновлений розрахунок.
>
> З повагою, команда агенції.

(52 слова — у межах ліміту; для довшого прикладу з реальними умовами оплати
довжина зросте до 100-150 слів, як вимагають acceptance criteria.)

> **Нотатка про діалект:** без відчутної різниці у тексті листа. XML трохи
> краще тримає "нуль вигаданих чисел" завдяки явному `<no>` на цю тему поруч
> із `<context>` де перелічені джерела чисел — легше перевірити самому собі,
> що кожна цифра в тексті має пару в контексті.
